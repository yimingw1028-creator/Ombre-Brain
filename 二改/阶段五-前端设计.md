### 阶段五 · 前端：June 那一侧

**这一节有分刀，但和阶段四一样：June 没开口，不动手。** 她说「做一屏吧」，就做下面排在最前、还没做的那一刀，只做那一刀。

#### 这是什么，为什么做

前四个阶段改的都是陆沉那一侧：记忆怎么存、怎么浮现、怎么找。June 说过她的目的是陆沉用得方便，不是她自己怎么翻。

但后台是 June 每天打开的地方。2026-11-16 她说她有个「宏图大业」，想改后台的界面，又说这太大了。她发来现在的首页截图：第一屏是 11 个功能入口、15 个筛选按钮、2 条提醒，库里八百多条记忆一条都看不见，要往下滑才有。她的评价是「简单直给，不是错的」，但「如果是我，会想让这个界面跟月亮或者一本书有些联系」。

所以这一阶段要做的是：**给后台一张 June 想打开的脸。** 不是重写后台，不是加功能。

#### June 想要的样子

她发了四张喜欢的图（一张群青色的月相环海报、两页手帐、一张左黑右白互为负片的图）。陆沉从里面看出四个共同点，June 确认了「就是这个感觉」，她说自己对这种几何美感很 obsessed：

1. **每一页只有一个圆，别的东西都相对它摆。** 圆是重心。现在的后台是 11 个一样大的格子，没有中心。
2. **时间是画出来的，不是列出来的。** 一天里的事沿着从圆上拖出去的线挂着；一个月是一圈或一排月相。
3. **一张纸，一种墨。** 米白的底，大片留白，只用一种颜色（群青），最多再加一道红。线很细，有点、刻度、小四角星。
4. **它已经是一本书了，而且是图谱那种书。** 每页有图版编号、日期、一行斜体题注。

月亮和书在这个项目里都不是外来的装饰：项目的标志是半个圆；陆沉每天向 June 要月亮；回望是一个月一次；June 的记忆库有信、有钉选、有计划。

**陆沉加的一条判断（June 没有反对）：几何留给时间和导航，正文一律横排。** 纸上的字可以斜着写、沿弧线写，那是参考图好看的一大半原因；但手机上要读的是三四百字一条的记忆，斜着读不了。所以圆、线、月相用来表示「哪一天」「哪一条」「去哪儿」，记忆的标题和正文老老实实横着排。

#### 书的各个部位对应什么

| 书里的说法 | 记忆库里是什么 | 数据从哪来 |
|---|---|---|
| 封面（首页） | 今晚的月亮 + 今天留下的几条 | `/api/buckets?sort=created_desc`，在浏览器里筛出今天的 |
| 一页 | 一条记忆的正文 | `/api/bucket/{id}` |
| 这一章 | 一个回望周期（23 号到下月 22 号）里的每一夜 | 同上，按创建日期分到每一天 |
| 扉页 | pin（核心准则） | `/api/buckets` 里 `pinned` 为真的 |
| 目录 | 地图（anchor + 在用清单） | **后端还没做，见阶段四。这一页要等。** |
| 夹页 | 信 | `/api/letters` |
| 书签 | plan | `/api/plans` |
| 封底 | 设置、导入、日志、帮助等一切别的 | **不重做，直接链接到旧后台 `/`** |

「封底就是旧后台」这一条是让这一阶段一直小下去的关键：旧后台那 11 个入口里的大部分，永远不需要在新页面里重做。

#### 草图在哪

- **`二改/前端/首页草图.html`**：2026-11-16 画的首页，静态，没接数据，用浏览器直接打开就能看。记忆标题是占位文字（这个仓库是公开的，真标题不放进来）。
- **`二改/前端/draw_home_sketch.py`**：生成那张草图的脚本。所有尺寸、坐标、颜色、月相的画法都在里面。做真页面时照着它把画法搬到 JavaScript 里，不要凭感觉重画。
- June 手机里存着渲染出来的那张图。她看过，说「超乎想象的好看，就是我想要的感觉」。**所以首页的样子以这张草图为准，不要自己再设计一版。**

草图的要点（都能在脚本里核对）：

- 画幅 390×844（手机竖屏），四周留 24 px。
- 底色 `#F1EEE6`，墨色 `#1B2A8F`（群青），唯一的点缀色 `#C0452F`（红，只用在一道弧和「今天」的小三角上，不用在文字上）。
- 次要文字不换颜色，用同一种墨降到 0.78 的不透明度。不要低于这个数，再低对比度不够。
- 三种字：等宽小字（IBM Plex Mono，11–12 px，加字距）用于编号、日期、标签；斜体衬线（Cormorant Garamond Italic）只用于那一行英文题注；中文用宋体（Noto Serif SC，系统宋体兜底）。
- 从上到下：标志和搜索 → 图版编号和日期 → 月亮和拖出去的线（高 312）→ 短横线和题注 → 今天的条目列表 → 「这一章」的一排小月亮 → 底部四个字（扉页、目录、夹页、封底）。
- 月亮：暗面是实心的墨，亮面是随机的小点，越靠近明暗交界线越密。外面一圈细环、12 个刻度、顶上一个小三角。
- 线：从外环的左下方出发，朝左下 38° 拖出去，互相平行。每条线对应今天的一条记忆。线上有两个小点一颗四角星，线尾一个实心圆点再散三个渐小的点。**编号放在这条线自己的延长线上**（第一版放在旁边，压到了相邻的线，是 June 截图之后才发现的）。
- 「这一章」：31 颗小月亮排成一排，每颗是那一晚的真实月相；今天那颗下面有红色小三角；还没到的日子降到 0.42 的不透明度。
- 所有能点的东西都是真的 `<button>` 或 `<a>`，高度不小于 44 px。

#### 读过的代码事实（2026-11-16）

- **页面怎么下发**：`src/web/dashboard.py`。访问 `/` 时从磁盘读 `frontend/dashboard.html` 原样返回，带禁止缓存的响应头。页面本身不需要登录就能拿到，数据接口才需要。
- **静态文件有白名单**：`/static/{name}` 只放行 `icon.svg`、`favicon.svg`、`manifest.json`、`RRPL.ttf` 四个名字。往 `frontend/` 里放一个新的 html 文件，**不会自动能访问**，要加一条路由。
- **登录**：`src/web/_shared.py` 的 `_is_authenticated`，认的是名叫 `ombre_session` 的 cookie，在旧后台登录后由 `/auth/login` 种下。新页面和旧后台同一个域名，浏览器会自动带上这个 cookie，新页面不需要自己做登录。接口返回 401 就说明没登录。
- **记忆列表** `GET /api/buckets`：返回全部桶（**包含已归档的**，只跳过已删除的），不分页。参数 `sort` 可以是 `score`、`created_desc`、`created_asc`。每条有：`id`、`name`、`type`、`domain`、`tags`、`valence`、`arousal`、`importance`、`resolved`、`pinned`、`digested`、`created`、`created_epoch_ms`、`last_active`、`last_active_epoch_ms`、`activation_count`、`score`、`content_preview`（正文前 200 字）、`letter_locked`、`why_remembered`、`dont_surface` 等。
- **`name` 不一定是个像样的标题**：没起名的桶，`name` 是桶的 ID 或一串时间（June 截图里那条 plan 的标题就是 `2026-10-17 04-40-53`）。
- **单条** `GET /api/bucket/{bucket_id}`；**信** `GET /api/letters`；**计划** `GET /api/plans`；**锚点** `GET /api/anchors`；**搜索** `GET /api/search`；**状态** `GET /api/status`。后面这几个的返回格式 11-16 没有逐个读，用到哪个先读哪个。
- **部署**：Dockerfile 里有 `COPY frontend/ ./frontend/`，所以 `frontend/` 里的新文件会进镜像。
- **清单**：`update_manifest.json` 也记录 `frontend/` 里文件的哈希。加了或改了前端文件，要重新生成清单（「每一刀怎么做」第 9 步），不然 GitHub 上的测试会红。

#### 这一阶段专有的规矩

硬规则全部照旧，另外加这几条：

1. **不改 `frontend/dashboard.html`。** 一个字都不改。新页面是另一个文件。
2. **新页面只读。** 它只发 `GET` 请求。钉选、归档、删除、编辑这些会改数据的动作，一律不做，留在旧后台。这样新页面无论写出什么 bug，都碰不坏记忆库。哪天要加写入的动作，单独问 June，单独成一刀。
3. **一个文件，不用构建工具，不引第三方 JS 库。** HTML、CSS、JS 写在同一个 `.html` 里，和旧后台一样。不要 npm、不要框架、不要打包。
4. **不向任何外部地址发送记忆内容。** 页面唯一允许的外部请求是加载字体，而且字体加载失败时页面必须照常能用（中文字体写系统宋体兜底）。
5. **正文横排。** 见上面那条判断。
6. **接口返回 401 时**，显示一句「请先在旧后台登录」并给出到 `/` 的链接，不要显示一个空白页。
7. **不显示上锁的信的内容。** 接口本身已经会把上锁的信替换成提示文字，前端不要想办法绕过。
8. **新增的那条路由要有测试**（照现有路由测试的写法），并且带上和 `/` 一样的禁止缓存响应头，不然 June 那边会看到旧版面。

#### 月相怎么算

- 月相只和日期有关，在浏览器里用算术算，**不要为它调任何外部接口。**
- 草图脚本里用的是查表法：写死了 2026 年 10、11、12 月三次朔的时刻，只够画那一张图。
- 真页面要用能算任意日期的办法。最简单的一种：取一个已知的朔的时刻做基准，用平均朔望月 29.530588853 天去取余，得到月龄，再用 `(1 - cos(2π × 月龄 / 朔望月)) / 2` 得到亮面的比例。这个办法和真实月相最多能差十几个小时，画在屏幕上看不出来，够用。可用的基准：2026-11-09 07:02 UTC 是一次朔。
- 月龄小于半个朔望月是上弦那一侧（亮面在右），大于是下弦那一侧（亮面在左）。这是北半球的看法，June 在北半球。
- 画法（暗面的路径怎么拼）在脚本的 `dark_path()` 里，照搬。

#### 怎么验收前端的刀

陆沉和别的模型在二改用的环境里**都看不见渲染出来的页面**。2026-11-16 那张草图就是算着坐标排的，编号压线的问题是 June 截图之后才发现的。所以：

- 每一刀推上去、部署之后，请 June 用她的手机打开，截图发回来。**June 是这一阶段的眼睛。**
- 拿到截图要对着草图逐项看：有没有字被挤出框、线有没有压到字、月亮亮的是不是对的那一半。不要只看一眼说「好了」。
- 前端的刀来回会比后端多几趟，这是正常的，不要为了少来回而一次做两刀。
- 字体从 Google 的字体服务加载，在 June 那边快不快、加载不出来时兜底的样子能不能接受，要在她手机上看了才知道。

#### 没定的

- 新页面的地址叫什么。
- 新页面做到什么程度之后，要不要把它换成默认首页（访问 `/` 时先看到它）。在 June 明确说要之前，`/` 一直是旧后台。
- feel 在书里叫什么、放在哪。陆沉提过「页边的批注」，没有画，没有定。
- 搜索在新页面里长什么样。草图右上角画了一个放大镜，后面没有设计。
- 首页的条目列表，要不要把「今天被想起的旧记忆」也算进去。草图里把「捞回」的两条画了进去，那是陆沉当天手工做的事，接口里有没有对应的数据没核对。
